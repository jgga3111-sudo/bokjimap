## 3. 가장 중요한 발견 — 네이버와 구글이 정반대다

같은 주제로 두 곳에서 검색해 봤다.

### 네이버 웹문서: 정부·공공기관이 독점

`에너지바우처 신청 대상 지원금액` 상위 10건 → **전부 .go.kr / .or.kr**
(에너지바우처 통합센터, 복지로, korea.kr, 한국에너지공단, 서울에너지공사…)

`청년월세 지원 신청 조건` 상위 12건 → **전부 정부·지자체**
(복지로, 국토교통부, 마이홈, 부산청년플랫폼, 서울주거포털, 인천청년포털…)

해피나눔도 지원금비서도 **개별 사업명 쿼리에서 한 건도 안 보인다.**
해피나눔이 1위를 잡은 건 `내가 받을 수 있는 지원금 찾기` 같은 **도구성 쿼리**뿐이다.

### 구글: 민간 콘텐츠가 상위에 올라온다

`청년월세 지원 2026 신청조건 소득기준` 상위 →
**brunch.co.kr(1위)**, 복지로, **토스뱅크**, 부산청년플랫폼, 서울주거포털,
**opcl.kr**, brunch

민간이 1위와 3위를 잡았다.

### 여기서 나오는 결론

**우리 전장은 구글이다.** 러닝온도 실적의 근거가 GSC 데이터였으니 일관된다.
네이버는 개별 사업 쿼리에서 사실상 진입이 막혀 있다고 보고, 기대치를 낮게 잡는다.

## 4. 마라톤과 복지의 결정적 차이 (docs/02 보정)

docs/02에서 "러닝온의 `/races`처럼 개별 개체 페이지가 주력"이라고 결론 냈다.
그 방향은 유지하되, **전제 하나가 다르다는 걸 이번에 확인했다.**

| | 마라톤 대회 | 복지 사업 |
|---|---|---|
| 공식 페이지 | 없거나 부실 (소규모 주최) | **복지로에 100% 존재하고 충실** |
| 러닝온/복지맵의 역할 | 흩어진 것을 처음으로 모음 | 이미 모여 있는 것을 다시 모음 |
| 원문 그대로 옮기면 | 유일한 정보원 | **중복 콘텐츠** |

**상세 API 본문을 그대로 붙이는 것만으로는 복지로를 이길 수 없다.**
원문은 근거로 싣되, 그 위에 복지로에 없는 것을 얹어야 한다.

복지로에 없는 것:
- **조회수 순위** — 복지로는 인기순 정렬을 노출하지 않는다
- **가구원 수 × 소득 → 어느 기준선까지 열리는지 한 화면 판정**
  (복지로 모의계산은 사업별로 따로 들어가야 한다)
- **지역 페이지에 중앙부처 사업 병기** — 복지로는 축이 분리돼 있다
- 사업 간 비교·연결 (같은 대상의 다른 지원)
